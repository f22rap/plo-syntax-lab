# 複数ボードの一括調査

2026-10-14、第3ステップ。確認用EXEの版は `2026.10.14-research-run`。

## 操作

1. 集計タブの「調査条件セット」で、ユーザーが設定したsyntaxを選ぶ。
2. 「ボードCSV登録」で、調べるカタログを選ぶ。登録方法は[調査設定の手順](research-setup.md)を参照。
3. 最高ランク（登録条件に従う／全ボード／Ahi〜2hi）、分類方法、試行数、シードを指定する。
4. 「登録ボードを一括調査」を押す。登録時からのCSV変更確認後、各ボードを順に計算する。
5. 同じ集計タブに結果が開く。「ボード別」と「特徴別（等重み）」を切り替え、表とEQ×アクション頻度のグラフを確認する。
6. CSV・JSON・SVG・Markdownを保存できる。SVGは現在選択中のボード別／特徴別の表示を出力する。

登録したカタログを使うため、通常の単一ボード入力欄やCSV欄へボードを1つずつ読み込む必要はない。syntaxを自動で追加・修正しない。ボード別syntaxが未設定なら、初期設定では実行前に止める。「syntax未設定を欠損として続行」を選んだ場合だけ、その行を欠損として記録して続ける。

相手レンジが未登録なら初期設定では止める。「相手未登録は頻度のみ」を選ぶと、該当ボードではアクション頻度と条件のレンジ内比率を計算し、EQは欠損にする。相手レンジを一様レンジに置き換えることはない。

## ボードの分類

初期対象はPLO4・2人・フロップ。AhiはAを1枚以上含むフロップとする。

| 選択肢 | 分類 |
| --- | --- |
| スート構成 | レインボー／ツートーン／モノトーン |
| ペア構成 | アンペア／ペア／トリップス |
| スート × ペア | 上記2軸の組合せ |
| A以外のランク構成 | Aの枚数、T〜K・6〜9・2〜5の枚数 |

分類版は `flop-texture-v1`。同じカタログでもアクション位置・ノードが異なれば別の集計群にする。ストレートのつながりなどの分類は今回追加していない。

## 計算と平均の意味

- 自分のアクション前レンジは、そのボードに登録した全アクションCSVの物理ハンド別weight合計。
- 相手レンジは、そのボードに登録した複数CSVを既存インポート処理で統合。
- EQは既存のEquityEngineで計算する。自分weight×相手weightと合法な対戦組を使用し、現在のアクションでレンジを絞らない。
- 頻度は既存のEquityFrequencyPlanで計算する。相手のブロッカーによって頻度の分母を変更しない。
- フロップのEQはモンテカルロ計算。同じボード・syntax・CSV・試行数・基準シードなら、既存の単一ボードEQと同じ派生シード・結果になる。
- 同じボード内の重複syntaxは計算を再利用するが、条件ID・表示名は別々に残す。
- 条件の「レンジ内%」は、その条件が自分のアクション前レンジのweightの何%を占めるか。条件は重複し得るため、条件別の比率を合計しない。
- 特徴別の平均は、有効な登録ボードの等重み平均。CSV総weightやボードの自然発生確率で重み付けしない。

アクションは種類とポット比率で対応付ける。CSVの順序や表示ラベルだけでは対応付けない。Bet 33%とBet 75%は別系列。あるボードに存在しないサイズを0%として平均しない。「総ベット」はbetの合計で、raiseを含まない。総ベットは表に表示し、散布図は個々の実アクションを表示する。

表には頻度の平均・最小最大・有効数・対象数・アクション存在数、EQ平均・有効数を表示する。図はEQと頻度が両方ある同じ対象の平均を使用するため、「図の頻度」「図のEQ」「図の共通対象数」を別に表示する。例えば2ボードに頻度があり、そのうち1ボードだけEQがある場合、表の頻度平均は2ボード、図の点はその1ボードを使う。

カテゴリ全体の信頼区間は算出しない。ボード別の図にはEQのモンテカルロ95%区間を表示する。ボード間のばらつきと計算誤差は別のものとして扱う。

## グラフ

すべての実アクションを表示する。色は研究全体でアクションの種類・サイズに固定され、CSVの並び順が変わっても同じ系列として扱う。

点にカーソルを合わせると、ボードまたは分類、条件名、syntax、アクション、EQ、頻度、出典を確認できる。特徴別では、各ボードで使ったsyntaxをボード別表・JSONから確認できる。同一座標に複数アクションが重なる場合は点を色分けし、説明には重なった条件をすべて含める。座標をずらして値を変えない。SVGも同一座標の説明をまとめる。

## 欠損・中止・入力変更

- `missing_definition`：そのボードのsyntaxが未設定。
- `no_matching_hands`：自分のアクション前レンジに該当ハンドなし。
- `frequency_only`：相手レンジなし。頻度のみ計算。
- `equity_unavailable`：合法な対戦組がない等でEQ計算不能。計算済みの頻度は残す。
- `failed`：CSV検証・読込等が失敗。数値を0として補わない。

実行前に全対象CSVのSHA-256を登録時と照合する。さらに各ボードの読込前後・計算後にも確認する。変更を検出したら不確かな数値を確定しない。CSVを編集した場合は登録画面で再検証する。

「調査を中止」で停止できる。中止時は、確定済みのボードだけを保持し、全体を `cancelled` と記録する。未完了のボードは平均に含めず、対象数には残す。計算中の1ボードの途中の条件結果は確定しない。閉じる操作でも中止し、処理が終わってから閉じる。

## 保存・再現

結果は履歴保存先の `Research/Runs/<結果ID>.json` に自動保存する。「調査結果JSONを開く」で再表示できる。元CSVを読み直さず、保存した結果を表示する。

JSONにはカタログと条件セットのID・版・内容、全入力パスとSHA-256、分類版、試行数・シード、ボード別の使用syntax・状態・数値を保存する。CSVはボード別行と特徴別行を含む。Markdownは計算方法、局面条件、比較表、ボード別の結果、出典を含む。報告書にAIの戦略解釈を自動追加する機能はまだない。

調査設定・結果JSONは別形式。設定JSONは「設定JSON読込」、結果JSONは「調査結果JSONを開く」で扱う。出力で入力CSVや調査設定ファイルを上書きしない。

初期上限は1調査200ボード、10,000条件行、合計1億試行、各条件1〜2,000,000試行。自分は2〜3アクション。上限を超えた場合は設定を減らすよう表示し、試行数を黙って下げない。結果JSON・SVGの出力上限は64MiB。

## 検証と残る段階

追加した64チェックで、既存EXEとの同一入力・同一シードのEQ/頻度一致、等重み平均、CSV順序とサイズの対応、ノードの分離、欠損と図の共通対象、中止、CSV変更、保存・復元・出力を検証した。第2ステップまでの20,904チェックと合わせ20,968チェックがLinux .NET 8で通過した。

Windows製品EXEと操作テストEXEはコンパイル済み。操作テストには複数ボードの完了、図の切替、結果欄の展開、自動保存、中止を追加した。Windows実機での画面操作は未確認。出力SVGはレンダリングして確認した。

MCPへの公開、特定AIホストへの接続、自然文からの調査実行と根拠付きの解釈は第4ステップ。既存MCPのツール契約やクラウドサービスは今回変更していない。登録された戦略CSVを調べる機能であり、未提供ボードの戦略を新しく解くソルバーではない。

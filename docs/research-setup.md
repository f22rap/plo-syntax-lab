# ユーザーsyntaxと複数ボードCSVの登録

この文書は第2ステップの設定操作を説明します。現行の一括調査は[複数ボードの一括調査](research-run.md)を参照してください。

2026-10-14、第2ステップ時点。ウィンドウタイトルは `2026.10.14-research-setup`。

## 今回使える機能

「集計」タブの相手レンジ設定の下に「調査条件セット」「ボードCSV登録」の2行を追加した。別のトップレベルタブは増やしていない。編集はこの画面から開くダイアログで行う。

条件セットを保存し、現在のフロップへ適用して従来の「集計＋EQ計算」で使える。複数ボードのCSVと局面条件を登録・保存できる。登録カタログからの一括計算、ボード特徴による横断集計、MCP公開は後続ステップであり、登録しただけでは計算しない。

## syntaxの設定

1. 「調査条件セット」の「新規」を押し、セット名を入力する。
2. 「追加」で条件を作り、条件名と「この条件を使用」を設定する。
3. 適用方法を選ぶ。
   - **全ボード共通**：`AA`、`A:!AA`などのsyntaxを入力する。その文字列をそのまま使う。
   - **ボード別に指定**：スート付きフロップとsyntaxを表に入力する。例えばAsKd7cにAK、Ah8h3cにA8を指定できる。
4. 「検証して保存」で保存する。空のsyntaxや不正な構文は保存しない。
5. 集計画面にボードを入力し、セットを選択して「現在ボードに適用」を押す。使用する条件のボード別定義が不足していれば、適用全体を中止する。
6. 自分のCSVと相手レンジを指定して、従来どおり集計・EQ計算する。

「現在ボードに適用」はsyntax生成モードの現在の選択条件を置き換える。暗黙の「全ハンド」追加は行わない。全ハンドを調べたい場合は `*` という条件をセットへ明示的に追加する。ボードを変更すると従来どおり現在の条件をクリアするので、セットを再適用する。

既存の生成画面やデフォルトから選択した条件は「今の選択条件を保存」でセットへ取り込める。生成済みsyntaxは、そのボード専用の定義として保存する。生成時の役の意味から別ボードのsyntaxを自動生成しない。

フロップの3枚の順序は同一として扱う。ランク・スートは変更しない。`ss` はスペード2枚のままであり、ボードのフラッシュスートへ読み替えない。現在対応するのは既存SyntaxMatcherの構文。任意のMonker構文すべてへの対応を意味しない。

## 複数ボードのCSV登録

1. 「ボードCSV登録」の「新規」を押す。
2. カタログ名と共通の局面条件を入力する。初期版はPLO4・2人・フロップ。同じカタログのポジション、スタック、ポット種別、アクション履歴、レーキ・ソルバー設定、EQ基準点をそろえる。異なる場合は別カタログを作る。
3. 「ボードとCSVを追加」でフロップとアクション位置を入力する。
4. 自分の各アクションに、表示名・種類・CSVを設定する。bet/raiseはポット比率を入力する（33%なら0.33）。自分は全アクションの2〜3CSV、weightは0〜1。
5. 相手レンジは「相手CSVを追加（複数可）」で登録する。全ファイルのフルパスが表示される。共通weight単位を0〜1または0〜100から選ぶ。
6. 全アクション・共通weight基準の確認欄をチェックし、「CSVを検証して登録」を押す。
7. 必要なボードを追加して「カタログを保存」を押す。

CSV登録は本文、手札、weight、ボードとの重複、自分の合算ハンド数、相手の統合ハンド数、SHA-256を確認する。検証失敗・中止時は以前の登録内容を変更しない。相手レンジを省略した場合は頻度調査用の登録とし、EQを計算可能とは扱わない。検証はレンジ同士の全合法対戦組や実際のEQをまだ計算しない。

自分のアクションCSVは手札の重複行を拒否する。相手のCSV内の重複は既存インポートと同じ最大weight、ファイル間は加算。同じ種類・サイズのアクションや同じCSVの二重登録は拒否する。同じカタログ内の同一ボード・同一アクション位置も二重登録しない。

## 保存とJSON

設定は履歴保存先の `Research/workspace.json` へ保存する。通常は `%LOCALAPPDATA%\FlopCommandApp\History\Research\workspace.json`。条件セット・カタログにIDと版を持ち、変更した対象だけ版を進める。同時編集の古い保存は拒否する。ファイル破損時はエラーを表示して元ファイルを保持する。

「設定JSON保存」で条件セットとカタログを出力し、「設定JSON読込」でコピーとして追加する。CSV本体は含まず、ファイル名を含むフルパスと登録時のハッシュを含む。別PCでは各ボードを編集してCSVのパスを設定し直し、再検証する。元CSVが後から変更・移動されても自動で読み直さない。後続の一括計算ではハッシュを再確認する設計。

[条件だけの読込サンプル](research-settings-example.json)はこの実装で読込可能。第1ステップの `ai-research-example.json` は当時の設計例で、実行用の形式ではない。実装は1カタログに1つの共通局面条件を置き、複数カタログで複数の局面条件を管理する。

## 検証

研究設定の54チェックを追加。syntaxの保持、ボード順序、未定義・不正・重複の拒否、複数CSVの検証、ハッシュ変更検出、保存・再読込・コピー、競合・破損時の保持を確認した。既存EQ関連の20,850チェックと合わせ20,904チェックがLinux .NET 8で通過した。

製品EXEとWindows操作テストEXEをC# 5／.NET Framework 4.8参照でコンパイル。操作テストには条件の適用、未設定ボードの拒否、再起動後の復元、編集画面の生成を追加した。この環境ではWindowsデスクトップの表示・操作テストは実行できていない。

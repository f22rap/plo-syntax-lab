## 計算定義

現在のボード・局面へ到達した時点の両者のレンジを使う。それ以前のストリートによる絞り込みは維持し、この局面のベット・チェックでは絞り込まない。

自分のアクション前レンジをsyntaxで抽出する。双方の重みを `h_i`, `v_j` とすると、カードが衝突しない対戦組 `(i,j)` を `h_i × v_j` に比例して選ぶ。重みの正規化は合法対戦組全体で行う。自分のハンドを固定したまま相手だけ引き直して平均する方式とは異なる。

- 全アクションCSVが共通のweight基準なら、物理的に同じハンドごとにweightを加算して自分の元レンジを復元する。
- `FromActions` は共通基準の確認が必須。個別に正規化されたアクションのweightを自動復元しない。別途入力した元レンジも利用できる。
- 同一レンジ内の重複指定は最大weightを採用する。アクション間の加算と混同しない。既存CSVの重複行エラーは今後のCSVアダプターで維持する。
- ベットサイズ・ベット頻度をEQエンジンへの入力に含めない。グラフでは同じsyntaxのEQを各サイズで共有できる。
- 条件間でハンドが重複しても、各syntaxは独立した対象集合として計算する。

## ファイルとAPI

`src/EquityEngine.cs` は追加依存のないC# 5互換コード。カードIDは既存の `src/SyntaxMatcher.cs` と同じ A〜2、s/h/d/c 順。

| API | 用途 |
| --- | --- |
| `EquityRange.Parse(text, token)` | 添付仕様の簡易レンジを全具体コンボへ展開。固定コンボ、4ランク、ワイルドカード、スート構成、重み、除外に対応 |
| `new EquityRange(combos)` | 検証済みの具体コンボ・相対重みから構築 |
| `EquityRange.FromActions(actions, commonScaleConfirmed)` | 全アクションをハンドごとの加算で統合 |
| `range.SelectSyntax(syntax, token)` | 既存C# matcherでsyntax抽出。空集合を全ハンドに変換しない |
| `EquityEngine.Prepare(board, hero, villain, token, progress)` | ボード除外・対戦可能なコンボの選別・合法対戦組数を算出 |
| `EquityEngine.Calculate / CalculateAsync` | 厳密／モンテカルロ計算。非同期版は設定値をコピーして実行 |

`EquityCombo` と `EquityRange` は構築後に内容を変更できない。UIは入力のスナップショットを作り、ジョブIDで古い結果を抑制する予定。

自分側のsyntaxと、相手入力の簡易レンジ記法は別の文法。相手側に未対応の括弧式を渡した場合はエラーにする。CSVのデコード・列認識・重み単位の変換は次段階の入力アダプターの担当。

## 判定・試行・全列挙

- 52枚、PLO4ハイ、2人、フロップ〜リバー。
- 手札2枚と最終ボード3枚の全60通りを評価。A2345、キッカー、全役に対応。
- ランク評価を13^5要素のキャッシュに保持し、フラッシュを別判定。評価器はジョブごとに独立。
- 既知カードとの衝突を除外。各側について相手に合法な組がないコンボも除外する。
- 合法対戦組数は整数の包除原理で求める。小さい有効weightを消す可能性がある「重み総和の引き算」での判定は行わない。
- フロップ・ターンはモンテカルロ。合法な対戦を選んだ後、残りの物理カードから一様・非復元抽選でボードを補完。
- 候補対戦組が50,000以下なら合法対戦組の積weightを直接抽選。それ以外は双方をそれぞれweightに比例して抽選し、衝突したら双方を引き直す。
- 試行数は1〜2,000,000。衝突した抽選は有効試行数に含めない。誤差による早期終了なし。
- 32ビットxorshift、シード未入力は暗号学的乱数で生成。シード0は `0x9e3779b9` を内部状態に使う。同一入力・設定・実装で再現可能。
- リバー全列挙は双方の全合法対戦組を積weightで集計。各ハンドの役は先に一度だけ評価する。
- 全列挙の既定上限は候補対戦組5,000,000。上限超過時はエラーとしてモンテカルロの明示選択を求める。勝手に計算方式を変更しない。事前計算からUIで件数を表示可能。
- 広いレンジと極端なweightで合法組の抽選確率が低い場合、モンテカルロでも時間がかかる。抽選回数と有効試行数を別々に通知し、中止可能。

EQは `(勝ち + 引き分け/2) / 全集計 ×100`。引き分け率自体は半減しない。95%区間は添付仕様と同じ正規近似。全列挙の誤差幅は0。数値のアンダーフローで正の対戦weightが0になった場合はエラーにし、黙って落とさない。通常の浮動小数点・乱数分解能の制約は残る。

結果にはEQ、相手EQ、勝ち/引き分け/負け、区間、方式、シード、有効試行/列挙件数、抽選/検査回数、両側の対象件数と除外件数、合法対戦組数、計算時間を保持する。`ElapsedMs` は `Calculate` 内の時間であり、別APIのレンジ展開・`Prepare` の時間は含まない。画面で総所要時間を示す場合は全処理を計測する。

中止は `OperationCanceledException`。完了結果を返さず、途中結果は進捗通知のみ。UIで確定値・保存済み結果として扱わない。

## 検証

独立した5枚役・60通りオマハ参照実装、および合成レンジを使用。

- 5枚役20,000件、オマハ役500件で一致。ボードだけのストレート/フラッシュを採用しない。
- 全270,725コンボ、AA 6,961、AKQJのds 36／ss 144／r 24／ts 48／mono 4。
- 添付の重み付きリバー例は厳密EQ25%、引き分けのみならEQ50%。
- 添付の固定ハンド・フロップ例の有効相手コンボ数は4,595。独自実装のシード123・10,000試行はEQ68.48%。添付実装の68.84%とのビット単位一致は要求しない。
- 独立した積weightの厳密集計と一致。双方を入れ替えるとEQ合計100%。自分固定→相手だけ再正規化する誤実装を検出するケースも通過。
- 密なレンジで衝突拒否方式を通り、独立した厳密値とモンテカルロ結果を比較。
- 固定両ハンドの全物理ランアウト（フロップ・ターン）を独立列挙し、試行結果と比較。
- フロップrandom対randomは各211,876コンボ、合法対戦組31,568,464,620。計算前処理＋10,000試行はこの検証環境で約1.6秒。端末別の性能保証ではない。
- 重複最大weight、全アクション加算、syntax抽出、微小weight、不正入力、空集合、全衝突、同一シード、シード0、前処理中止、抽選中止、全列挙中止、処理上限を確認。
- 合計20,605チェック通過。C# 5、.NET Framework 4.8参照アセンブリでエンジンのコンパイル成功。テストの実行環境はLinux上の.NET 8。

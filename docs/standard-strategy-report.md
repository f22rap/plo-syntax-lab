# Ahit 初手・標準4条件レポート

Node.js版の **PLO-Syntax-Lab-Windows-MCP 0.5.0** に、ボード分類 → 共通4条件選定 → ブロック平均 → 50%判定 → 固定PDFを追加した。追加のPythonや外部PDFサービスは不要。日本語フォントとライセンスを同梱する。

呼び出し例：**「PLO Syntax Labで、保存済みカタログのAhit標準4条件レポートを作成。既存5ブロック、50%基準、固定PDFで」**。

## 導入先と対象

- リポジトリ直下の `mcp/server.mjs` が提供するNode.js版。`src/mcp` の旧接続、クラウド版、Node.js不要の接続EXEには追加されない。
- Windows buildの `PLO-Syntax-Lab-Windows-MCP` パッケージを更新し、既存の `mcp.local.json`、入力CSV、履歴を引き継いでMCPを再起動・再接続する。`get_status.version` が `0.5.0`、全40ツール中、調査25ツールが見えることを確認する。リポジトリへの追加だけでは、既に起動中のローカルMCPは更新されない。
- PLO4・2人・A-high・レインボー・アンペアのフロップ。フロップで完成ストレートが存在しないボードに限定。
- AhitはAがちょうど1枚、残り3枚にボードの他2ランクを含まないもの。2ペア・セット・AAを含まない。
- 同一局面・同一チェック＋1ベットの完全なアクションメニュー。共通スケールのweightを確認済みのカタログを使用。ベットサイズが異なるボードを同じ集計に混ぜない。相手CSVやEQはこの頻度分析には不要。
- カタログ登録・CSV参照は既存のスコープ制約、リビジョン、SHA-256検証を使用。ソースの変更を検出した場合は失敗し、古い結果へ黙って差し替えない。

## MCPの呼び出し

最初に `research_list_workspace` と `research_list_spots` で、対象カタログ・現在のrevision・局面・ボードを確認する。ディレクトリから始める場合は既存のscan/importを使い、局面メタデータやアクションメニューを推測しない。

```json
{
  "catalog_id": "選択したID",
  "catalog_revision": 1,
  "spot_ids": [],
  "classification": "approved-five",
  "create_pdf": true
}
```

これを `research_build_strategy_report` に渡す。空のspot_idsはカタログ全体。ジョブIDを `research_get_job` で完了まで確認する。成功するとreport_id、各ブロックの4条件、PDF artifactが返る。失敗理由はジョブのerrorに保持する。

| ツール | 用途 |
|---|---|
| `research_build_strategy_report` | CSVから分類・4条件選定・平均・判定・固定PDFを一括作成 |
| `research_get_strategy_report` | `metadata`で定義・ハッシュ・選定得点、`cells`でブロック平均、`board`で検算用のボード別セル。ページをすべて読む |
| `research_list_strategy_reports` | 再起動後も保存レポートを検索 |
| `research_export_strategy_report` | 保存済みreport_idからPDFまたはJSONを再出力。CSVやEQを読み直さない |

`get_artifact` または `plo://artifacts/{artifact_id}` で取得できる。PDFはUTF-8文字列として読まず、base64のblobで返す。大きな出力は返されたローカルpathを使用する。artifact_idはセッション内、report_idと保存結果は再起動後も有効。保存ファイルはoutputRoot内のUUID名とし既存ファイルを上書きしない。

## ボード分類

既定の `approved-five` は合意済みの `ahi-five-v1`。選択されているボードだけを使用し、欠けているボードを補完しない。

| ブロック | ボード |
|---|---|
| G1 | AJ3 / AQ6 / AJ7 / AT7 / AT6 |
| G2 | A63 / A65 / A73 / A82 / A96 |
| G3 | AQ9 / AJ9 / AT9 |
| G4 | AK5 / AK9 |
| G5 | A87 |

未知のボードをこの5ブロックへ推測で割り当てない。

- `classification: "effect-cluster"` と `block_count: 5`：今回の頻度傾向から再分類する。キッカー／BDFD／PP／SD／ブロッカーの条件族を均等化した条件別頻度差を作り、コサイン距離・平均連結法で指定数へまとめる。ブロッカーはSDなしだけで比較。ゼロベクトル同士の距離は0、一方だけゼロなら1。同距離はカタログ順で決定する。指定数が最適という主張はしない。
- `classification: "custom"` と `blocks: [{"id":"G1","boards":["A82"]}, ...]`：明示した分け方を使う。選択ボードが重複なくちょうど1回ずつ含まれる必要がある。

## 4条件の定義と選定

候補は16枠。SDを必須とする **455組** を全探索し、ボードごとの説明分散を等重みで平均して最大化する。同点は平均絶対誤差、条件名順。選定後はSDを論理上の入口に固定し、残る3条件を条件付きの追加説明力順で並べる。SDが単条件で最も効くという意味ではない。各ブロック内ですべてのボードに同じ4条件を適用する。

細分セルは候補16枠の同時分類。ボード内ではアクション前weightで加重し、原子的な頻度の分散を基準とする。説明分散は `Σ q_cell p_cell² − p_board²`。比較対象を一定にし、サンプル数の多いボードを過大評価しない。これは条件との関連を測る記述的な説明力で、因果効果やEV改善量ではない。

| 枠 | 状態・意味 |
|---|---|
| SD（必須） | なし／4アウツ全ナッツ・非ナッツ／8アウツ全ナッツ・非ナッツ／9+全ナッツ・一部ナッツ・ナッツなし。存在しない状態の行は出力しない |
| BDFD / BDFD3枚以上（1枠） | いいえ／いいえ、はい／いいえ、はい／はい。ボードにあるスートが手札2枚以上でBDFD。2+2は「はい／いいえ」 |
| PP（1枠） | SDなし：なし／22／22以外のSDブロックPP／その他。SDあり：なし／22／22以外のPP（ブロック対象外） |
| キッカー（2候補） | ボードにない最上位ランク、または上位2ランクの有無。通常K／KQ、AKxではQ／QJ |
| SDブロック（11候補） | OESD構成カードあり・2枚以上・3枚以上、最高／最低OESDコア、ナッツガット構成カード、ガット構成カード、SD構成カード2枚以上・3枚以上、OESDコア2種類以上・3種類以上 |

SD完成はPLOの手札2枚＋ボード3枚に限定し、ターンの残存実カード枚数を数える。4・8アウツは全アウツがナッツの場合だけナッツ。ナッツは自分の4枚とボードを除いた合法相手の最高ストレート高との比較で、フラッシュ等の役との比較ではない。ラップを単一ガットへ混ぜない。2完成ランクがあってもOESDとは限らず、例えばA73の54はダブルガットでOESDコアには含めない。

全SDブロック条件とPPのSDブロック区別は **自分にSDがない時だけ**。SDありは「対象外」であり、いいえではない。PPは同ランク2枚以上（3枚も含む）、22を優先。ペア自身のランクがSDコアに含まれるかを判定し、サイドカードのブロックと区別する。SD構成カードの枚数は物理カード数なので同ランク重複も数える。OESDコア種類数は2枚組の種類数で、1枚が複数コアを抑える場合もある。

## 平均・判定・PDF固定形式

アクション前weightはcheck+betの合計、ベット頻度はbet weight／合計weight。片方のCSVに行がない場合、そのアクションweightは0として共通スケールの完全メニューを復元。両方0は母集団に含めない。CSV内の重複・不正ハンドはエラー。

各ブロックの同じ4条件セルについて、正のアクション前weightを持つボードの頻度を等重み平均する。該当しないボードは分母から外し、0%のボードは含める。**丸め前の平均が50%以上ならベット、未満ならチェック**。表示は小数1桁。例えば49.999%は50.0%と表示されてもチェック。JavaScript Numberによる近似値であり、小数の厳密演算を主張しない。

固定テンプレート `ahit-landscape-v1`：A4横、日本語フォント埋込、紺の見出し、条件優先順、SD別の2列表、青の頻度ヒートマップ、緑のベット・茶のチェック。各セルに平均の有効ボード数を併記。対象外は灰色。未成立・該当なしを0%やチェックとして補完しない。ルール、PP・SDランク一覧、出典IDを付ける。行数によって改ページするためページ数は固定しない。

保存JSONには、全ボード別セル、ブロック平均、選定上位10組、条件順・増分説明力、元CSVハッシュ、カタログrevision、コード・フォントハッシュを保持する。現在のテンプレート版と異なる保存レポートはPDF出力を拒否する。PDF再出力は保存数値を利用するが、PDFバイナリの日時・文書IDまで同一になる保証はない。

## 検証

`npm ci` 後、`npm run test:strategy`。合成CSVのみで、PLOアウツ・ナッツ、BDFD2+2／3+、PPの重複カード、SDブロック対象外、A82/A87の別分類、455組選定、等ボード平均、境界50%、カタログ・CSV更新、保存／再起動／PDF再出力を検証する。個人CSV・実戦略の数値はリポジトリへ同梱しない。

Windowsの既存MCP接続・ネイティブ計算テストはWindows buildで実行する。ローカルの既存0.4.2プロセスへの再接続確認は、配布パッケージ更新後に別途必要。

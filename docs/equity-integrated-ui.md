# 集計画面へのEQ統合（2026-10-13）

「集計」でCSV比較とEQを続けて実行できるようにし、独立したEQタブを廃止した。

## 操作

1. 集計画面でボード・全アクションCSV・syntaxを選択する。
2. 同じ画面の「相手のアクション前レンジ」にテキスト入力、または「CSV読込（複数可）」から1個以上のCSVをまとめて選択する。
3. 自分のアクション前レンジは、集計に入力した全CSVの合計に固定。同じ物理ハンド（カード順序は不問）のweightを加算する。自分のレンジの手入力・均等指定はない。共通weight基準であることを確認する。全CSVのアクションが自動でグラフに表示される。
4. 「集計＋EQ計算」を押す。CSV集計が終わると、同じ条件でEQを計算する。
5. 結果の「グラフ」にCSV比率とEQ×アクション頻度を横並びで表示する。「表」にはCSV集計表とEQ結果表をまとめる。EQ専用タブへの移動や追加の計算ボタンは不要。

ベットCSVの指定は不要。CSV1は青、CSV2は緑、CSV3は橙で表示し、凡例にはCSVのラベルを使う。チェック・フォールド等のCSVも含め、選択した全CSVを使用する。各CSVを個別に正規化せず、ハンドごとの合計weightを保持してsyntaxで抽出する。相手レンジは別に入力する。

試行数・シード・リバー全列挙・上限組数は「詳細設定」で開閉する。入力と結果は同じ集計ページ内にあり、画面の高さに応じて縦スクロールする。実行開始時は結果エリアへ移動する。

相手レンジCSVは `hand,frequency,percent,weight,ev,ev_diff,variations` の7列形式に対応する。`weight`（または「重み」）があれば優先し、ない場合のみ `frequency` 等を使う。`percent`・`ev`・`ev_diff`・`variations` はEQの重みに使わない。提示の形式では重み単位を「0〜1」にする。

CSV・JSON・SVG保存とEQ履歴は、同じ結果エリアの下部に配置した。既存のCSV比較履歴は従来の履歴タブで参照する。

## 実行・中止・エラー

- 実行開始時点のボード、syntax、双方のレンジ、全CSV、設定を使う。
- 集計からEQ終了まで入力を固定し、共通の中止ボタンで停止する。
- 集計が失敗・中止した場合はEQへ進まない。
- EQが失敗・中止した場合は、完了したCSV集計結果を残し、EQの理由を表示する。
- 新しい集計の開始時に古いEQグラフと確定結果を消す。
- ボードや入力の変更で処理を中止し、遅れて届いた結果を表示しない。
- CSVの組とラベルが同じままsyntaxだけを変える場合、共通weight確認を保持する。CSVが変わる場合は再指定する。
- 相手レンジ・共通weight確認が不足する場合、EQまたはグラフを推測で補わず理由を表示する。
- 外部アプリによるCSVファイルの変更は監視しない。処理中にCSVを書き換えないこと。

EQ画面からの新規計算は必ず全CSV合計を使用する。過去の保存結果を読めるよう、内部のレンジ種別とアーカイブ形式は保持している。

この環境ではWindows実機の起動・画面操作を実行できないため、上記操作テストとレイアウト確認は未実施。計算・保存の回帰テストには、CSVを個別正規化しない合計weight、合計レンジとEQの一致、ベット指定からの独立性、カード順序が違う同じハンドの合算を追加した。計20,850チェックが通過。

配布用EXEは、対象コミットのGitHub Actions「Windows build」で生成する。ビルド成功とWindows実機での画面操作確認は別の検証として扱う。

対戦可能ハンドの照合とsyntax抽出を高速化。[変更内容と速度検証](equity-performance.md)を参照。

グラフの点にカーソルを合わせると、条件名・syntax・アクション・EQ・アクション頻度を即時表示する。重なった点は該当する条件をすべて表示する。点から離れる、スクロール、リサイズ、結果の再計算時は表示を消す。集計結果とEQ履歴のグラフに共通。Windowsでの実画面表示は未確認。

相手レンジCSVの読込に成功すると、双方のレンジ欄の直下にある横幅いっぱいの「相手レンジCSVの保存先（フルパス）」専用欄に、ファイル名を含むフルパスを表示する。パスは読み取り専用で選択・コピー可能。長いパスは折り返して表示し、縦スクロール・選択・コピーができる。読込の失敗・中止時は、直前に成功した読込元を保持する。

全CSVについて、同じハンド条件のEQを共通の横軸値とし、縦軸に各アクションの頻度を表示する。有効な条件では全アクション頻度の合計が100%となる。頻度0%のアクションも点を表示する。旧履歴にもアクション別頻度が保存されていれば全アクションを表示する。

保存JSONの旧`BetActions`とCSVの旧`is_bet`列は互換性のため保持する。新規計算ではアクション種別を推測せず、`BetActions`は空配列・`is_bet`は空欄。グラフの対象には使わない。

現行版のウィンドウタイトルには `2026.10.13-multi-range` と表示する。未読込時にも専用欄を表示する。読込失敗の理由は相手レンジ欄の下にも表示し、前回成功したパスは残す。読込情報用の高さ44pxの領域にパスを押し込まず、独立した72pxの行を確保し、集計画面の高さにも反映した。

Windows操作テストには、実際の読込処理を経たパスの反映、日本語と空白を含む保存先、最小ウィンドウサイズでのパス欄の配置、失敗時の保持を追加。製品・操作テストEXEのコンパイルは確認済み。Windows実機でのテスト実行・表示は未確認。

## 複数の相手レンジCSV

- ファイル選択画面でCtrl／Shiftを使って複数CSVを選択できる。再読込時は今回選んだファイル一式で置き換える。
- 同じ物理4枚のハンドは、カードの並び順にかかわらずCSV間のweightを加算する。CSVをそれぞれ正規化しない。共通のweight基準で出力されたCSVを使う。
- 1ファイル内の重複・重なる簡易レンジは従来どおり最大weightを採用する。その後、ファイル間で加算する。
- 統合後のweightが1を超える場合は、テキスト欄の形式に合わせて統合全体を同じ倍率で縮小する。ハンド間の重み比率とEQは変わらない。画面に「相対weight表示」と表示する。
- 読込済みファイル数・統合後のハンド数と、全ファイルのフルパスを表示する。全パスは履歴とJSONにも保持し、結果保存で入力ファイルを上書きしないよう保護する。
- 有効なweight 0のファイルは統合への寄与0として扱う。全ファイルの合計が空ならエラー。
- 同じパスの二重指定は拒否する。CSVが1つでも不正な場合、または中止した場合、元のレンジとファイル一覧を保持する。
- 7列CSVのweight優先、CSV単位0〜1／0〜100、UTF-8／Shift_JIS、簡易レンジの対応は維持する。

# 保存したデフォルト条件でAIにボード調査を依頼する

第4段階の実装です。Node.js版MCPから、保存した条件を各ボード用syntaxへ変換し、CSV集計・アクション前EQ・グラフ出力まで実行できます。未公開の開発版です。

## 利用する流れ

1. アプリの「集計 → 調査条件セット → 新規 → デフォルト条件から追加」で条件を選び、保存します。条件名は変更できます。
2. 既存の接続設定でNode.js版MCPを起動します。今回の版では31ツールを公開します。
3. AIへ、調査するディレクトリ／登録済みカタログ、最高ランク条件、保存した条件セット名を指定します。
4. AIが対象CSVと条件セットを確認し、`research_validate`を呼びます。ジョブが完了すると、対象ボード、生成syntax、空集合、未設定、計算設定を確認できます。
5. 計画を確認してから`research_start`を呼びます。完了後、ボード別・特徴別の結果を取得し、`research_export`でCSV・JSON・SVG・Markdownを出力します。

依頼例：

> 登録済みのCOvsBTNカタログから、Khiボードのベット戦略を調べてください。条件セットは「私の調査条件」を使ってください。まず対象ボードと生成されたsyntaxを示してください。確認後にEQと全アクション頻度を計算し、特徴別に比較してください。

A、K、Q、その他の最高ランクを指定できます。KはAを含まないKhiです。条件セットやAhiへの置き換えは行いません。ディレクトリからの登録は既存の`research_scan_directory`／`research_import_directory`を使います。

## 条件と結果

- `research_list_default_presets`はアプリと同じ185項目を安定したID・名称・対応状況付きで返します。159項目が選択可能です。保存はユーザの指定に従って行います。
- 条件名ではなく、保存したプリセットIDまたはフィルターから生成します。改名しても条件IDは維持します。
- 例えばトップセットは`AsKd7c`で`AA`、`Kh9h3c`で`KK`になります。手入力した固定`AA`はそのままです。
- 同じ物理ボードが別ノードにある場合、生成は1回です。集計・EQは各ノードの入力CSVで個別に行います。
- 自分のアクション前レンジは全アクションCSVのweightの合計です。相手は登録された複数のアクション前レンジCSVを統合します。相手レンジが不明なら推定で補いません。
- 同じ条件IDでボード間を比較します。グラフは全アクションを色分けし、ポイントの説明に条件名・ボード・syntax・出典を含めます。

| 状態 | 意味 | EQ・アクション頻度 |
| --- | --- | --- |
| `empty_condition` | そのボードで条件を満たす合法ハンドが存在しない | 未計算・null |
| `no_matching_hands` | 合法ハンドは存在するが入力CSVに該当しない | 未計算・null |
| `missing_definition` | 手入力のボード別定義が未設定 | 明示的に許可した場合だけ行を保存、数値はnull |
| `unsupported_recipe` | 条件版・プリセットが未対応 | 計画を作らず停止 |
| `generation_failed` | 生成失敗・時間切れ | 計画を作らず停止 |

空集合とCSV内の該当なしを頻度0%としてプロットしません。カテゴリ平均は既存仕様どおり、有効な登録ボードを等重みで集計します。

## 変更検知・中断・保存

検証時に元の条件セット、物理ボード、生成syntax、合法ハンド数、条件ハッシュ、生成コードの版とハッシュを固定します。実行前に設定の版、CSVハッシュ、生成コードを再確認します。変更があれば再検証が必要です。

生成中の中断では計画を作りません。EQ計算中の中断では、全条件が確定したボードだけを保存します。保存結果は形式2で、生成スナップショットのUTF-8 JSONとSHA-256を含みます。再起動後は保存した定義を読み、現在の生成処理で再生成しません。従来の手入力条件だけの結果は形式1を維持します。

JSON出力とメタデータで生成の詳細を確認できます。CSV・SVGにはボードごとの条件名と使用syntaxを出力し、Markdownには生成ハッシュも記録します。

## 対応範囲と検証

通常アプリでの条件選択・保存と、Node.js版MCP経由の生成・調査を接続しています。アプリの直接実行ボタンとNode.js不要の接続EXEからの自動生成実行は、次の対応範囲です。手入力条件の既存実行経路は維持しています。

Linux上で同じC#計算コードを.NET 8へコンパイルし、公式MCP SDKのstdio通信で、保存→生成→CSV集計→実EQ計算→全形式出力→再起動後の読込を検証します。検証用CSVを使用しており、ユーザのFドライブ上の実データは使用していません。Windows向けEXEはクロスコンパイルで確認します。Windows実機での起動・画面操作・トンネルからの接続確認は未実施です。

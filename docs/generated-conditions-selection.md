# デフォルト条件を選んで保存する

第3段階では、アプリの「集計」画面から、デフォルト条件を選んで調査条件セットに保存する機能を追加しました。選択・保存にはボード入力もNode.jsも不要です。保存した定義からボード別syntaxを生成する確認用CLIはNode.js 20以上を使います。

第4段階で、保存した条件をNode.js版MCPの一括調査に接続しました。[AIからの調査手順](generated-conditions-research.md)に従うと、ボード別syntaxの生成、CSV集計、EQ計算、グラフ出力まで実行できます。アプリの「現在ボードに適用」「登録ボードを一括調査」ボタンからの自動生成実行と、Node.js不要の接続EXEでの自動生成実行は未接続です。これらの経路は計算前に説明を表示して停止します。MCPで保存した調査結果は、アプリから読み込めます。

## 操作手順

1. **集計 → 調査条件セット → 新規**を開きます。既存セットへ追加する場合は「編集」を選びます。
2. **デフォルト条件から追加**を押します。
3. 条件名で検索し、使いたい条件にチェックを入れます。検索語を変えてもチェックは保持されます。
4. **選択した条件を追加**を押します。
5. 条件セット名を付け、**検証して保存**を押します。

185項目をSyntax Labと同じ名称・順序で表示します。159項目が対応済みです。旧一覧で定義がない26項目は理由付きの「未対応」として表示し、選択できません。

現在のボードで0件になり得る条件も保存できます。例えば「Mset all」はペアボードで該当しなくても、別のボードで利用するために選択しておけます。

「表示中の選択可能条件を選択」「表示中の選択を解除」は、検索結果に表示されている追加可能な条件だけを操作します。別の検索結果で選んだ条件は保持されます。条件セットに登録済みの項目は「選択済み」と表示し、重複追加しません。削除する場合は、条件セット編集画面の左側の一覧で選び「削除」を使います。

## 保存される内容

- 条件セット名、各条件の表示名、使用チェック、条件ID。
- 元のデフォルト条件IDと定義の版。
- 必要に応じて追加した固定syntax（AND条件）。指定なしは `*`。

表示名を変更しても元の条件は変わりません。生成済みの `AA` や `KK` を別ボードへ持ち回る形式にはせず、「トップセット」などの定義を保持します。

手入力の共通syntax・ボード別syntaxと、自動生成条件を同じセットに保存できます。既存の「今の選択条件を保存」は、従来どおり現在ボードのsyntaxを保存します。

「追加syntax」は固定条件です。例えば `AA` を追加すると、KhiでもAAを含むハンドに絞ります。トップランクのポケットへ自動変換されません。

編集画面でキャンセルすると元の条件セットは変更しません。保存後はアプリを開き直しても、選択した条件・名前・使用チェック・IDが復元されます。

## 保存した条件をCLIで確認する

アプリの **設定JSON保存** で、例えば `plo-research-settings.json` に書き出します。

```powershell
node mcp/preview-generated-conditions.mjs --set plo-research-settings.json --list-sets
```

表示された目的の `set_id` を指定します。

```powershell
node mcp/preview-generated-conditions.mjs --set plo-research-settings.json --set-id 対象のset_id --boards AsKd7s,Kh9h3c --output selected-preview.json
```

セットが1個だけなら `--set-id` は省略できます。結果の読み方は[生成プレビュー](generated-conditions-preview.md)を参照してください。CLIは元の設定JSONを変更しません。

## 旧設定の扱い

手入力条件だけの既存設定は保存形式1のまま利用できます。自動生成条件を初めて保存すると形式2へ移行し、既存ファイルがある場合は、同じフォルダーに `workspace.json.schema-v1.r<旧revision>.bak` を作成します。

バックアップ作成と設定更新は同じ保存ロックの中で行います。バックアップに失敗した場合や別画面で設定が更新された場合は、元設定を置き換えません。移行後は自動生成条件を削除しても形式1に戻しません。旧版アプリは形式2を読み込まず、エラーとして停止します。

未対応の定義の版や、新しい設定項目を読み捨てて保存することはありません。新しい項目を含む設定は、対応する版で開いてください。

## 検証範囲

保存・移行・競合時の保持、旧条件との混在、C#の保存JSONとNode版の互換性を実行テストで確認します。Windows向けアプリとUI操作テストもコンパイルします。

Windowsの実画面でのクリック操作、DPI・画面サイズごとの表示、配布EXEの起動確認は、Windows環境で別途行う必要があります。コンパイル成功を起動確認済みとは扱いません。

## ppをランク別に出力

「デフォルト条件から追加」で「pp条件をランク別に出力」をオンにすると、選択した pp over / pp under が22〜AAの独立した13条件として追加されます。オフでは従来の一括条件です。
保存済みの自動生成条件は、編集画面で選び「選択条件をppランク別に分割」を押すと分割できます。元の条件を13条件に置き換え、SD・BDFD・追加syntax・有効/無効の設定を引き継ぎます。保存するまでは元の条件セットに影響しません。

各条件のポケットランクは固定ですが、Thitなどの役とボード相対条件は毎回生成します。AT6でのAhit＋66・TT・AAなどは「該当なし」になり、EQゼロとは扱いません。独立した条件IDと表示名を持つため、既存の集計・EQグラフ・エクスポートでもランクごとに表示します。

A44・A77・AJJのように下位ランクがペアのフロップでは、Thitは単独のトップランクをヒットしたハンドを含みます。トリップス・フルハウス以上を除外し、AA3などトップランク自体がペアのボードはThitに読み替えません。A44のThit allは `A!(4,AA)` になります。実際のポーカー役の強さやEQ評価は変更しません。

更新後はアプリとMCPを再起動し、古い検証プランを使わず再検証してください。過去の保存済み計算結果は変更されません。
